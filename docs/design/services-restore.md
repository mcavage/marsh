# Services restore (S4)

Restore turns a snapshot of a workspace's services (`capture.rs`) into a **fork** in another
workspace's scope (a lane). It runs in the services agent, inside `marsh-svc-engine`, and every
engine call it makes on the user's behalf goes through the policy (`docs/design/services-policy.md`).
Design: ENG-PLAN D3, SECURITY-DESIGN A2, A4, A8, A9.

## Two phases

The Mac daemon writes the lane's files (A9: `compose.fork.yaml` and `.env`), so restore is split
around that write.

| Phase | Relay frame | Answer |
|---|---|---|
| prepare | `restore_prepare{request, id, workspace, project, source?, lane_dir, fork}` | `restore_prepared{request, result}` |
| up | `restore_up{request, workspace, project, source?, lane_dir, fork}` | `restored{request, result}` |

`project` is the folder the services VM mounts (the project's root); `lane_dir` an absolute path
strictly inside it, where the daemon put the lane's copy of the checkpointed folders. `source`, when
present (C3), is the folder the checkpointed stacks' folders are relative to if that is not `project`:
a lane's own checkpoint records the first lane's folder, and a second lane is not inside it. It must be
inside `project`; a stack's folder in the lane is its recorded working directory minus `source`. The agent validates `fork` (a compose project name of at
most 48 characters), `workspace` (the policy's workspace-id rule) and both paths as names, then resolves
`lane_dir` beneath a descriptor it holds on `project` (`openat2` with `BENEATH`, `NO_SYMLINKS`,
`NO_MAGICLINKS`, `NO_XDEV`). A stack's folder inside the lane is the stack's recorded working directory
minus `project`, resolved the same way.

**prepare**, per compose stack in the snapshot: read its configuration with the confined client
(`docker compose config --format json`), refuse it with a named reason if it uses `container_name`, an
external or explicitly named volume or network, or a published port range (other stacks go on), create
a fork volume `<fork project>_<key>` for each volume the snapshot saved **through the filter** (so it is
in the lane's scope and ledger, with compose labels), and install the snapshot's data: a reflink clone
into a staging directory beside the new volume's `_data`, checked (entry count against the manifest), and
swapped in with `renameat2(RENAME_EXCHANGE)`. The volume is new and unused, so nothing can be reading it.
It then returns, without writing anything:

```
{ projects, restored, fresh, gaps, failures, ports, files, timing_ms, ok }
```

`files` maps `compose.fork.yaml` and `.env` (prefixed by the stack's folder when it is not the lane
folder) to their contents. The override is generated by a serializer from validated keys and numbers
(`ports: !override`, remapped to free loopback ports inside the engine, `name: <fork project>`). The `.env`
is the lane's own `.env` with `localhost:<port>` and `127.0.0.1:<port>` rewritten, any old
`COMPOSE_PROJECT_NAME` and `COMPOSE_FILE` dropped, and those two lines appended. Standalone volumes are
restored under `<fork>-<name>` and reported as `restarted: false`; Testcontainers objects are reported as
not restored; anything else with no saved data is `fresh`, with a reason. With one compose stack the
fork project is `fork` itself; with several, each gets `fork-<project>` (two stacks must not share a
project: each would see the other's containers as orphans).

**up**: checks that the lane's `compose.fork.yaml` and `.env` are the bytes prepare returned, runs
`docker compose up -d --wait` per stack, and then the fixed post-restore check: every expected service
has a container of the fork's project in the lane's scope that is running, and healthy where it has a
healthcheck (a one-shot service that exited 0 passes). No project script runs. A stack that does not
start is taken down completely (`down -v`, its volumes removed): no half-started fork. `ok` is true only
when nothing that should have been restored failed and the check passed; limits (a refused stack) are
gaps, errors (unreadable files, a volume that was not installed, a stack that did not start) are
failures.

## The compose client

The client never runs as root and never sees the production socket. The agent re-executes itself as
`marsh --internal-services restore-client`, which, in this order:

1. enters the stack's folder through the agent's descriptor (`/proc/<agent>/fd/<n>`);
2. confines itself with Landlock, **failing closed** (a kernel that cannot enforce all of it refuses):
   the lane folder is read-only, `/usr`, `/etc`, `/lib*`, `/bin`, `/sbin` and `/proc` are readable,
   the run directory's `home` and `tmp` are writable, and no TCP connection or bind is possible;
3. sets `no_new_privs`, drops supplementary groups and switches to the lane folder's owner (or `nobody`
   when that is root);
4. execs `docker` with only `DOCKER_HOST` (the restore's private socket under `/run/marsh-restore/`),
   `HOME`, `TMPDIR`, `PATH` and a few display variables.

The socket is served by the policy's endpoint with `Authority { project: lane_dir, workspace, attempt:
"restore" }`, so a hostile compose file (privileged, a root bind, a host network, a socket) is refused
by the same code that refuses it from a job, and bind sources are pinned beneath the lane. Files
the client cannot read (an `env_file` or `include` outside the lane) make that stack fail with the
operating system's "permission denied" and a gap that names the stack.

## Limits and notes

- A file in the lane that the Mac user made private (mode 0600, shown as root-owned in the VM) cannot
  be read by the unprivileged client; compose reports it and the stack fails with that reason.
- Prepared state is in the agent's memory. An agent restart between the two phases loses it; the
  daemon drops the lane's workspace (`drop_workspace`, below) and the restore is `ok: false`.
- The ports chosen in prepare are reserved in memory for ten minutes or until `up` ends.

## Break modes (test builds only; `marsh_contracts::break_mode` or the agent's `--break-modes`)

| Mode | What it breaks | Caught by |
|---|---|---|
| `restore-skip-volumes` | the data is not installed (silently: the entry count is skipped too) | RST-01 c1 (the fork's data is not the snapshot's) |
| `fault-restore-skip-volumes` | the same, with the entry count live | RST-08 (b): `ok:false`, nothing left behind |
| `restore-from-live` | volumes are copied from the original's live volumes | RST-01 c1; CAP-06 c2 |
| `restore-no-override` | no `compose.fork.yaml`, no port remap | the fork's up fails on the original's ports; RST-01 c2 |
| `restore-same-project` | the fork reuses the original's compose project name | the fork's volumes collide with the original's: `ok:false` |
| `restore-no-env` | the lane `.env` is not returned | RST-04 c1 (`.env` content), and the fork does not start as the fork |
| `restore-copy` | volume data is copied instead of reflinked | RST-06 c2 (extents shared, pool growth) |
| `restore-ignore-blockers` | stacks with fork-unsafe features are attempted | RST-10 c2 (the gaps no longer name them) |
| `slow-restore` | prepare waits 1.5 s | PERF-03 measurement control |
| `restore-unfiltered` (alias `restore-raw-engine`) | the compose client runs as root on the raw production socket | SEC-13 c1 (a privileged container exists) |
| `restore-client-unconfined` | the client is unprivileged but not confined | SEC-13 c2 (the file outside the lane is read) |
| `hold-restore-before-install`, `hold-restore-volumes-created`, `hold-restore-before-up`, `hold-restore-client-running` | harness barriers (the last waits in the helper, after it has dropped privileges) | SEC-13 c4 |

## Dropping a workspace (C3)

`drop_workspace{request, workspace}` -> `workspace_dropped{request, workspace, containers, volumes,
networks, left}`. The agent takes the workspace's operation lock (up to 60 s: a restore or capture of
it must end first), then through the filter **as that workspace** (authority `{project:
/run/marsh-restore/drop, workspace, attempt: drop}`; nothing resolves beneath that root) it lists and
removes the workspace's containers (`force`, with anonymous volumes), then its volumes, then its networks,
a few at a time, and lists again: what is still there is `left` (bounded, plain text). The filter shows
and accepts only the workspace's own objects, so the drop cannot name another's. Last,
`Services::forget_scope` forgets the scope's substituted sockets (their listener threads end and their
files go) and its default network entry in the ledger. Repeating it is safe.
