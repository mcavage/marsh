A shell for composing agents.

Run Claude, Codex, and Pi as commands, each in a fresh Linux container. Compose them with pipes and scripts, run concurrent edits on separate copies, and manage agents started by agents in one process tree.

Get started Read the manual

Apple Silicon Macs · Linux arm64 · Docker Sandboxes

Parallel work. Separate copies.

Both branches run at once, each on its own copy of your working tree, including uncommitted edits. Each make test checks that branch's changes.

join shows output, status, and patches. Inspect and apply the changes you want, then rerun tests on the combined tree. marsh does not merge automatically.

For work on shared files, fanout and collect run commands together, gather their output in order, and return a failing status if any branch fails.

Split and join →
Inside your marsh shell 
split {
  api: claude -p \
    "Add cursor pagination." &&
    make test
  cli: codex exec \
    "Add --json output." &&
    make test
} | join --keep

Example for an events project with an API, a CLI, and a make test target.

The same commands, inside an agent.

A Claude or Pi job can pipe a diff to Codex through its own shell tool. The call starts a child job in a fresh container, with the parent's project files unless it uses split. The answer returns on stdout, with an ordinary command exit status.

marsh tracks parent and children together. One Ctrl-C stops the foreground job tree. Enforced limits bound concurrent calls and nesting depth.

Why not scripts and worktrees?

Scripts already compose agent CLIs. Worktrees already separate edits. marsh manages execution and job lifetime alongside that composition.

Execution
Fresh nonroot containers inside Docker Sandbox VMs, with your project at its Mac path. Your real Mac home is not mounted. Register your own commands through Kits to use the same execution model for other tools.
Parallel edits
Copies include uncommitted changes and return inspectable patches, without adding Git branches or worktrees.
Job lifetime
Nested calls are tracked, bounded, and cancelled together. marsh results records whether container deletion was confirmed, including uncertain cleanup.

Know what your commands can reach.

Shell. The shell uses Bash-compatible Brush, with known gaps. Tests run on Linux, not macOS. Your own shell commands, including make test, run in the shell VM and are not confined to a split's copy.

Files and permissions. Direct agent calls can edit or delete the mounted project. In a split, those agents see their private copies. Jobs share marsh's guest home. The supplied agents run without permission prompts or their own sandboxes: the container and VM enforce the boundary.

Credentials. Proxy-managed API keys appear as placeholders, but saved guest logins are ordinary files other jobs can read. See the security model and commands and Kits.

Split copies omit ignored files and do not support linked Git worktrees. Split reference →
