A shell for composing agents.

marsh gives you a Linux shell in your project. Claude, Codex, and Pi run in their own containers and work with pipes, scripts, and Makefiles.

Repeat calls start quickly because marsh keeps the agent VMs running.

Split work at the prompt

Each branch is a shell command or pipeline running on its own copy of your files. Here, Claude works on the API while Codex works on the CLI.

For parallel commands that can share your working tree, such as tests and linters, use fanout { … } | collect. Split and join →

Why it starts quickly

Agent VMs
The first call to each agent prepares its VM and image, which can take a few minutes. Later calls reuse the running VM and start a new container for each job. You can register other tools to run the same way.
File branches
split snapshots the files you have now, including uncommitted work. It uses macOS copy-on-write clones where supported, so branching doesn't copy unchanged file data up front. Each patch is a diff against that starting snapshot, and marsh leaves your repository's branches and .git directory alone.

Agents can run agents

Claude can pipe its diff to Codex from its own shell tool. Codex runs as a child job and sends its answer back on stdout.

Cancel Claude and its child jobs stop too. marsh jobs --tree shows the calls, with limits on nesting and concurrent jobs.

What agents can change

The supplied agents run without permission prompts. A direct call can edit or delete your project; a split agent gets its branch's copy. Shell commands such as make test still run in the shared shell VM and can write outside the branch's copy.

Jobs share a guest home for agent settings and history. It is separate from your Mac home, but any job can read saved logins there. Docker Sandboxes supplies proxy-managed API keys without exposing their values to the jobs.
