How do you use marsh?

If you've packaged a tool or put a pipeline to work, share it in GitHub Discussions. Post the command you ran and what it produced.

GitHub Discussions → Contributing

Post in Show and tell

Open github.com/mcavage/marsh/discussions and start a thread in the Show and tell category. Include the command, the tool versions, and what happened when you ran it.

Kits

Link the Kit source and image digest, with the command to install it. Describe the network access it needs.

Registries

Show which tools you registered and how you use them together. Remove private settings before posting your commands.json.

Recipes

Paste the pipeline, its output, and any files needed to run it.

Include marsh --version and sbx version. Don't paste provider keys, saved logins, or private project files. Report bugs in Issues; report security problems privately.

Example: Pix

Pix is a coding and work agent that runs on marsh, next to the packaged pi. It's built in two layers.

Public Kit

Upstream Pi plus public skills, role prompts and themes, published as docker.io/mcavage/marsh-pix. Source and install.

Private layer

A second Kit built FROM the public image adds an organization's own skills. Work tools (mail, documents, the staff directory, the data warehouse) are small CLIs published as typed MCP tools; SBX injects their keys, so the agent never holds them.

Orchestration

No custom subagent runner: a skill teaches the agent marsh's fanout/collect and split/join.

To build your own, see Build your own agent.
