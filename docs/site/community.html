How to share

Post in Show and tell.

Open github.com/mcavage/marsh/discussions and start a thread in the Show and tell category. Good posts are short and runnable.

Kits

A tool or agent you packaged as a Docker Sandboxes Kit. Link the Kit directory, give the image by digest, and show the marsh kit install line.

Registries

Your commands.json: which names you register, and why. Say what each Kit's network policy allows.

Recipes

A split, fanout, or mcp publish line that saved you time. Paste the command and the part of the output that mattered.

Include marsh --version and sbx version. Leave out tokens, guest-home files, and private code. Bugs go to issues; security reports to SECURITY.md.

Two agents, one bug

Claude and Codex each fix the test on a private fork. join shows both patches; apply the one you like.

marsh-0.5$ marsh split -n \
>   ::: a claude -p 'fix the flaky test' \
>   ::: b codex exec 'fix the flaky test' \
>   | marsh join

A pipeline as a tool for Codex on your Mac

Publish a fixed pipeline from the marsh shell. Codex on the Mac calls it; it runs in the shell VM.

marsh-0.5$ mcp publish lint \
>   --description 'Run the linter' -- 'make lint 2>&1'
marsh-0.5$ exit
~/src/api $ marsh mcp install-published codex lint
~/src/api $ codex exec 'run lint and fix what it finds'

Agents running agents

Claude asks Codex for a second opinion. The call is a child job; one Ctrl-C stops both.

marsh-0.5$ export MARSH_SPAWN=codex
marsh-0.5$ claude -p "use your Bash tool to run: \
>   codex exec 'is this function correct?'"
marsh-0.5$ marsh jobs --tree

Tests and lint side by side

Both run at once on the same files. collect prints them in order and exits with the first failure.

marsh-0.5$ fanout {
>   test: make test
>   lint: make lint
> } | collect
